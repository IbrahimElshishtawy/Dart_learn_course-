# Lecture 04: Classes, Objects & The State Blueprint — دليل المحاضر
## دليل المحاضر الميداني: مدخل البرمجة الشيئية (OOP) وبناء الكائنات من الصفر للمبتدئين

> **فلسفة المحاضرة:**  
> ننتقل اليوم بالطالب من البرمجة الإجرائية (دوال ومتغيرات منفصلة) إلى **البرمجة كائنية التوجه (Object-Oriented Programming)**. لا نبدأ بتعريفات معقدة؛ بل نبدأ من العالم الواقعي: كل شيء في الحياة عبارة عن كائن (Object) له شكل وخصائص ووظائف. الكلاس هو مجرد "قالب الصب أو المخطط الهندسي"، والكائن هو المنتج الحقيقي الخارج من هذا القالب.

## 2. أهداف المحاضرة (Learning Objectives)
بنهاية هذه المحاضرة، يستطيع الطالب بمفرده:
1. شرح الفارق الحياتي والبرمجي بين الكلاس (Class) والكائن (Object).
2. كتابة كلاس متكامل يحتوي على خصائص (Fields) ووظائف (Methods).
3. إنشاء واستخدام دالة البناء (Generative Constructor) وفهم دور `this`.
4. حماية البيانات وتغليفها (Encapsulation) عبر الـ Private Fields `_` والـ Getters/Setters.
5. استيعاب الفارق بين مساواة المؤشر (Reference Equality `identical`) ومساواة القيمة (`operator ==`).
6. بناء كائنات مجمدة غير قابلة للتعديل باستخدام `const Constructors`.

### [الدقيقة 00:40 - 01:05] المستوى الثاني: حماية البيانات والتغليف (Encapsulation)
> **المحاضر يرسم قفلاً على شاشة العرض:**  
> "تخيل لو عندك حساب بنكي `balance = 1000;`، وجِه مبرمج زميلك في الفريق كتب: `account.balance = -50000;`!  
> هل منطقي نسمح لأي حد يمد إيده جوه الكائن ويعدل البيانات الحساسة بمزاجه؟  
> طبعاً كارثة! عشان كده في البرمجة عندنا مبدأ مقدس اسمه **التغليف وحماية البيانات (Encapsulation)**:  
> في Dart، أي متغير يبدأ بشرطة سفلية `_`، بيبقى **خاص وسري (Private)**:  
> مفيش أي كود برة الملف ده يقدر يلمسه مباشرة!  
> وعشان نخليهم يقرأوا القيمة بأمان، بنعمل باب مراقبة اسمه **Getter**:  
> ```dart
> class BankAccount {
>   double _balance; // سري ومحمي!
> 
>   BankAccount(this._balance);
> 
>   // Getter: باب للقراءة فقط!
>   double get balance => _balance;
> 
>   void deposit(double amount) {
>     if (amount > 0) {
>       _balance += amount;
>     } else {
>       print('خطأ: المبلغ المضاف يجب أن يكون موجباً!');
>     }
>   }
> }
> ```"

---

### [الدقيقة 01:05 - 01:35] المستوى الثالث والرابع: مساواة الكائنات وسحر `const`
> **المحاضر يكتب فخاً برمجياً على الشاشة:**  
> "بصوا للكود ده وقولولي النتيجة:  
> ```dart
> class Point {
>   final int x, y;
>   Point(this.x, this.y);
> }
> 
> void main() {
>   var p1 = Point(1, 2);
>   var p2 = Point(1, 2);
>   print(p1 == p2); // تفتكروا هيطبع True ولا False؟
> }
> ```  
> 90% من الطلاب هيقولوا: True لأن الأرقام متطابقة!  
> لكن لما بندوس Run.. النتيجة الصادمة بتطلع: **False**!  
> ليه؟  
> لأن Dart في العادي بتقارن **عنوان الذاكرة (Memory Reference)** مش المحتوى!  
> `p1` ساكن في شقة في المعادي، و `p2` ساكن في شقة في مدينة نصر؛ دول شخصين مختلفين حتى لو بيلبسوا نفس الطقم!  
> لو عايزهم يتساووا بقيمتهم، لازم نعمل Override لـ `operator ==` و `hashCode`.  
> 
> أما سحر **`const Constructors`**:  
> لو حطينا كلمة `const Point(1, 2)`، الـ Dart VM بتعمل حاجة عبقرية اسمها **Canonicalization**:  
> يعني بتقول: 'بما إن الكائن ده ثابت ومستحيل يتغير، أنا مش هحجز غير شقة واحدة بس في الذاكرة، وكل المتغيرات هتبص على نفس العنوان!'  
> وساعتها `identical(p1, p2)` هتبقى **True** وتوفر ملايين البايتات في الرام!"

## 5. أمثلة التدرج الرباعي (The 4 Code Levels)

### LEVEL 1 — SIMPLE (كلاس بسيط للمبتدئ):
```dart
class Student {
  String name;
  double gpa;

  Student(this.name, this.gpa);

  bool isHonors() => gpa >= 3.5;
}
```

### LEVEL 2 — INTERMEDIATE (تغليف ومعاملات مسماة):
```dart
class Product {
  final String id;
  final String title;
  double _price;

  Product({
    required this.id,
    required this.title,
    required double price,
  }) : _price = price > 0 ? price : 0.0;

  double get price => _price;

  void applyDiscount(double percent) {
    if (percent > 0 && percent <= 100) {
      _price -= _price * (percent / 100);
    }
  }
}
```

### LEVEL 3 — ADVANCED (مساواة الكائنات و Immutability):
```dart
class Coordinate {
  final int x;
  final int y;

  const Coordinate(this.x, this.y);

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is Coordinate && runtimeType == other.runtimeType && x == other.x && y == other.y;

  @override
  int get hashCode => Object.hash(x, y);
}
```

### LEVEL 4 — ENGINEERING LEVEL (نظام إدارة الإعدادات):
```dart
class AppConfig {
  final String environment;
  final String apiEndpoint;
  final int timeoutSeconds;

  const AppConfig._({
    required this.environment,
    required this.apiEndpoint,
    required this.timeoutSeconds,
  });

  factory AppConfig.development() => const AppConfig._(
        environment: 'dev',
        apiEndpoint: 'https://dev.api.example.com',
        timeoutSeconds: 30,
      );

  factory AppConfig.production() => const AppConfig._(
        environment: 'prod',
        apiEndpoint: 'https://api.example.com',
        timeoutSeconds: 10,
      );
}
```

## 6. حزمة التطوير البيداغوجي والهندسي (Cognitive Pack)

### أ. ملاحظات تطوير المحاضر (Instructor Development Notes)
- لا تستخدم مصطلح "Instantiation" قبل أن يفهم الطالب كلمة "خلق كائن حقيقي من القالب".
- ارسم الـ Heap Memory على السبورة ومثل كل كائن بمربع له عنوان مثل `0x10A`.

### ب. تمارين التفكير الإدراكي للطالب (Student Thinking Exercises)
1. *تمرين التتبع:* لو عندنا كلاس `Counter` فيه متغير `int count = 0;` ودالة `increment()`، وأنشأنا كائنين `c1` و `c2`. لو استدعينا `c1.increment()` مرتين، كم ستكون قيمة `c2.count`؟ (الهدف: إثبات استقلالية ذاكرة الكائنات).

### ج. سيناريو البرمجة الحية بالتفكير المسموع (Live Coding Think-Aloud)
- بناء كلاس `Wallet`، كتابة كود يتيح سحب مبالغ سالبة، إظهار كيف يؤدي هذا لزيادة الرصيد بدلاً من إنقاصه كخطأ أمني كارثي، ثم تصحيح الكود بالتحقق من المدخلات والتغليف.

### د. الأنشطة التفاعلية (Discussion Activity)
- مناظرة الـ `new` vs `const`: متى نلجأ للكائنات الثابتة ومتى نلجأ للمتغيرة؟

### هـ. فحص المفاهيم الخاطئة (Misconception Check)
- **الوهم:** *"تعديل خاصية داخل كائن يغير نفس الخاصية في كل الكائنات الأخرى المنشأة من نفس الكلاس"*.
- **التصحيح:** كل كائن يمتلك نسخته الخاصة المستقلة تماماً من الذاكرة في الـ Heap.

### و. التحدي الهندسي (Engineering Decision)
- هل نجعل كائنات الـ Model في التطبيق قابلة للتعديل (Mutable) أم مجمدة (Immutable)؟ ولماذا تفضل المعماريات الحديثة الـ Immutability؟

### ز. جسر المعرفة إلى Flutter (The Flutter Connection)
- في Flutter، كل واجهة تراها على الشاشة عبارة عن كلاس يرث من `StatelessWidget` أو `StatefulWidget`.
- استخدام `const` مع الـ Widgets يمنع إعادة رسمها ويوفر موارد المعالج بشكل مذهل.
