# Socratic Questioning & Classroom Inquiry System
## نظام الأسئلة السقراطية وإدارة الحوار التفاعلي في القاعة البرمجية

> **المبدأ الأساسي:**  
> جودة المهندس البرمجي تُقاس بجودة الأسئلة التي يطرحها على نفسه أثناء التصميم. المحاضر الذي يكتفي بسؤال *"مين مش فاهم؟"* أو *"ما تعريف الـ Polymorphism؟"* يقتل الفضول الهندسي لدى الطلاب. هذا الدليل يقدم بنكاً لنماذج الأسئلة العشرة (The 10 Question Archetypes) التي تفجر التفكير النقدي وتختبر الفهم العميق.

---

### النمط 1: أسئلة الاستكشاف والتعريف (What?)
- **الهدف:** فحص الإدراك المبدئي للمفهوم والتمييز بين المصطلحات.
- **مثال منطوق باللهجة المصرية التقنية:**
  > *"يا شباب، لما بنكتب `final List<int> numbers = [1, 2, 3];`، إيه بالضبط اللي أصبح `final` هنا؟ هل هو مؤشر الذاكرة ولا محتوى القائمة نفسها؟"*
- **الإجابة النموذجية ومعيار التقييم:**
  - *الإجابة:* مؤشر الذاكرة (Variable Reference) هو الـ `final`، ولا يمكن إعادة إسناد قائمة أخرى لـ `numbers`. لكن محتوى القائمة (The Heap Object) يظل قابلاً للتعديل (`numbers.add(4)` صحيحة) ما لم يتم تغليفها بـ `List.unmodifiable`.
  - *التقييم:* (1-5) يقاس بمدى وضوح التمييز بين Reference وObject في الذاكرة.

---

### النمط 2: أسئلة التعليل والسببية (Why?)
- **الهدف:** فهم القرارات الهندسية التي اتخذها مصممو اللغة أو النظام.
- **مثال منطوق:**
  > *"ليه فريق لغة Dart في جوجل قرروا سنة 2021 إن الـ Null Safety تكون Sound إجبارية في Dart 2.12 ومسمحوش بلغة مختلطة (Unsound) زي ما لغات تانية عملت؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* الـ Soundness الرياضية تعطي الـ Compiler ضمانات مطلقة (Guarantees) بأن المتغير غير القابل لـ Null مستحيل يحتوي على Null في الـ Runtime، مما يتيح للـ AOT Compiler توليد كود آلة أصغر حجماً وأسرع تنفيذاً لأنه يتخلص تماماً من فحوصات `null-check` التكرارية في المعالج.

---

### النمط 3: أسئلة الميكانيكية والتدفق (How?)
- **الهدف:** استيعاب كيفية سريان البيانات وتنفيذ الأوامر في بيئة التشغيل (Runtime Execution Flow).
- **مثال منطوق:**
  > *"ازاي الـ Event Loop في Dart بتنسق التنفيذ بين الـ Microtask Queue والـ Event Queue؟ مين بيدخل ومين بيستنى مين؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* الـ Event Loop تعطي أولوية مطلقة للـ Microtask Queue؛ لا تبدأ في سحب أي Event عادي إلا بعد أن تفرغ الـ Microtask Queue تماماً من جميع المهام المعلقة. وإذا أفرزت مهمة Event مهمة Microtask جديدة، تعود الـ Event Loop لخدمة الـ Microtasks فوراً.

---

### النمط 4: أسئلة الفرضيات والحدود (What If?)
- **الهدف:** اختبار متانة الكود وتخيل سيناريوهات الفشل عند تغير الشروط.
- **مثال منطوق:**
  > *"ماذا لو السيرفر بعت لنا JSON String فاضي `""` أو قيمة `null` في حقل `userId`، والكود بتاعك معتمد على `json['userId'] as String`؟ إيه الـ Exception اللي هيفرقع في وش العميل؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* سيرمي الـ Dart Runtime فوراً استثناء `TypeError: type 'Null' is not a subtype of type 'String' in type cast`، وسيتوقف التطبيق فجأة ما لم تتم معالجة الحالة بحقل اختياري `String?` أو قيمة افتراضية.

---

### النمط 5: أسئلة المقارنة والمفاضلة (Compare & Contrast)
- **الهدف:** تنمية حس المفاضلة المعمارية (Trade-off Analysis).
- **مثال منطوق:**
  > *"قارن لي بين استخدام `Mixin` واستخدام `Interface` في Dart. إمتى بتلجأ لده وإمتى بتلجأ لده؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* الـ `Interface` يفرض عليك عقداً فقط (Contract) وتضطر لإعادة كتابة كل الـ Implementations في كل كلاس، وهو ممتاز لتحقيق الـ Decoupling والـ Dependency Inversion. أما الـ `Mixin` فهو وسيلة لإعادة استخدام الكود الفعلي (Code Reuse) عبر كلاسات متعددة دون الدخول في مشاكل الوراثة المتعددة التقليدية (Diamond Problem) بفضل الـ Linearization.

---

### النمط 6: أسئلة التوقع والمحاكاة الذهنية (Predict the Output)
- **الهدف:** تدريب عقل الطالب على أن يكون محاكياً لبيئة التشغيل (Mental Dart VM).
- **مثال منطوق:**
  > *"بصوا على الكود ده على الشاشة:
  > ```dart
  > void main() {
  >   scheduleMicrotask(() => print('A'));
  >   Future(() => print('B'));
  >   Future.microtask(() => print('C'));
  >   print('D');
  > }
  > ```
  > قدامكم 30 ثانية بدون تشغيل الكود: رتبوا لي الحروف اللي هتطبع في الـ Console!"*
- **الإجابة النموذجية:**
  - *الإجابة:* الترتيب هو: `D` (الكود المتزامن أولاً) $\rightarrow$ `A` ثم `C` (طابور الـ Microtasks بأسبقية الإضافة) $\rightarrow$ وأخيراً `B` (من الـ Event Queue).

---

### النمط 7: أسئلة التحقيق واكتشاف الجذور (Debug & Root Cause Analysis)
- **الهدف:** تعليم الطالب قراءة الـ Stack Trace والوصول للسطر المسبب للمشكلة دون عشوائية.
- **مثال منطوق:**
  > *"العميل بيشتكي إن التطبيق بيعلق لمدة ثانية كاملة لما بيدوس على زرار الفلترة. فتحنا الـ DevTools ولقينا Frame Drop عنيف. تفتكروا إيه السبب في كود الـ Repository اللي مكتوب ده؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* وجود عملية فرز ثقيلة لقائمة ضخمة أو تشفير بيانات يتم تنفيذها مباشرة داخل الـ Main Isolate (UI Thread) بدلاً من تفويضها لـ Background Worker Isolate أو استخدام Streams محسنة.

---

### النمط 8: أسئلة التصميم والنمذجة (Design from Scratch)
- **الهدف:** تحفيز القدرة على التجريد وبناء الأنظمة من الصفر.
- **مثال منطوق:**
  > *"لو طلب منك تصميم نظام إشعارات (Notification Center) في تطبيق بنكي يدعم إشعارات الـ SMS، الـ Push Notification، والـ Email، إزاي هتصمم الـ Abstractions والـ Sealed Types والـ Factories بحيث لو أضفنا WhatsApp Notification بكرة منعدلش حرف في الكود القديم (Open/Closed Principle)؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* تعريف `abstract interface class NotificationSender`، واستخدام `sealed class NotificationChannel`، واستخدام `Factory Pattern` أو `Dependency Injection` لحقن الـ Implementations المستقلة.

---

### النمط 9: أسئلة التحسين والتعقيد الحسابي (Optimize)
- **الهدف:** الربط المباشر بين علوم الحاسب النظرية (Big O) وكفاءة الكود في الإنتاج.
- **مثال منطوق:**
  > *"الكود الحالي بيعمل لوب جوه لوب عشان يشوف هل العناصر مكررة، والـ Time Complexity طالعة $O(N^2)$. إزاي بكوليكشن واحدة في Dart ننزل بالزمن لـ $O(N)$؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* تحويل البحث إلى `Set` أو `HashMap` وتتبع العناصر التي تمت رؤيتها سابقاً، مستفيدين من سرعة الـ Hash Table Lookup في $O(1)$ amortized time.

---

### النمط 10: أسئلة الدفاع عن القرار الهندسي (Defend Your Decision)
- **الهدف:** بناء شخصية المهندس القادر على تبرير قراراته في جلسات الـ Architecture Review و الـ PR Reviews.
- **مثال منطوق:**
  > *"ليه في التحدي بتاعك استخدمت `Extension Type` بدل كلاس عادي؟ دافع عن قرارك واشرح لي وفرت إيه في الـ Memory على مستوى بيئة التشغيل؟"*
- **الإجابة النموذجية:**
  - *الإجابة:* الـ `Extension Type` في Dart 3.x هو ميزة Static-Only (Zero-Cost Abstraction). وقت الـ Compile Time يعطي نوعاً صارماً وواجهات محددة، لكن وقت الـ Runtime لا ينشئ كائناً جديداً في الـ Heap إطلاقاً ويتحول مباشرة للنوع الأساسي، مما يوفر استهلاك الذاكرة وتكلفة الـ Garbage Collection بنسبة 100%.

## 2. جدول توجيه الأسئلة بحسب التوقيت في المحاضرة

| دقيقة المحاضرة | نمط الأسئلة المفضل | الهدف من السؤال |
| :--- | :--- | :--- |
| **00 - 10** | `What?` + `Why?` | كسر الجمود وتنشيط الاستدعاء الذهني للمفاهيم الأساسية. |
| **10 - 35** | `How?` + `Predict` | التأكد من استيعاب النموذج التشغيلي وسريان الكود. |
| **35 - 60** | `Compare` + `What If?` | ربط المفاهيم واختبار سلوك الحدود والحالات الاستثنائية. |
| **60 - 90** | `Design` + `Debug` | التحليل المعماري وتفكيك الأخطاء في سيناريوهات الإنتاج. |
| **90 - 110** | `Optimize` + `Defend` | التحدي التفاعلي والمفاضلة بين بدائل الحلول. |
| **110 - 120** | `Exit Socratic Check` | سؤال ختامي تركيبي يربط المحاضرة بالمحاضرة القادمة. |
