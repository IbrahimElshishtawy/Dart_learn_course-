# Instructor Teaching Playbook — دليل أداء وتدريس المحاضر

## 1. فلسفة التدريس ودور المحاضر (Pedagogical Stance)

أنت لست مجرد ملقٍ للمعلومات، بل **Senior Dart Engineer & Technical Architect** يقود ورشة تدريبية احترافية تحاكي بيئة العمل في كبرى الشركات الهندسية.
الهدف ليس قراءة الشرائح أو سرد الكلمات، بل **تغيير النموذج العقلي (Mental Model)** للطالب، وتمكينه من التفكير المنطقي والهندسي قبل لمس لوحة المفاتيح.

## 3. أسلوب الإلقاء ونبرة الصوت (Tone of Voice & Egyptian Scripting)

### المبادئ الذهبية للإلقاء:
1. **المصطلحات التقنية تظل بالإنجليزية دائماً:**
   - قل: `Type System`, `Event Loop`, `Microtask Queue`, `Canonicalization`, `Heap Memory`, `Destructuring`.
   - إياك وتعريب المصطلحات بشكل يطمس معناها العالمي؛ وظيفتك هي شرح المصطلح الإنجليزي باللغة العربية البسيطة.
2. **استخدام اللهجة المصرية العامية الذكية في الشرح:**
   - اللهجة العامية المصرية التقنية تتميز بالقدرة على توصيل أصعب المفاهيم المجردة بأمثلة حياتية دقيقة وسريعة الوصول للذهن.
   - استخدم صيغ مثل:
     - *"تعال نبص في الـ Memory ونشوف الـ Dart VM بتعمل إيه هنا بالضبط..."*
     - *"ركز معايا في الحتة دي عشان 90% من الديفلوبرز بيقعوا فيها في الإنترفيوهات..."*
     - *"إحنا مش بنكتب كود يشتغل وخلاص، إحنا بنكتب كود يقدر يشيل Production Environment..."*
3. **لا تترك المفهوم نظرياً لأكثر من 5 دقائق:**
   - اربط كل نظرية مباشرة بكود حقيقي في الـ IDE، وقم بعمل `dart run` أو `dart analyze` فوراً لإظهار الأثر.

## 4. نموذج التدرج الرباعي في الشرح (The 4-Level Ascent Model)

عند شرح أي موضوع جديد، التزم بهذا الترتيب الصارم:

### LEVEL 1 — SIMPLE (البسيط):
- مثال من سطرين إلى خمسة أسطر.
- الهدف: إثبات الفكرة المجردة خالية من أي تشويش.
- مثال: إنشاء `Record` بسيط بقيمتين لمعرفة الـ Syntax الأساسي.

### LEVEL 2 — INTERMEDIATE (المتوسط):
- مثال يحتوي على دالة أو كلاس يتعامل مع منطق أعمال حقيقي (Business Logic).
- الهدف: إظهار كيف يتفاعل هذا المفهوم مع باقي أجزاء اللغة (Collections, Null Safety).

### LEVEL 3 — ADVANCED (المتقدم):
- مثال يدمج عدة مفاهيم متقدمة معاً (مثل: استخدام `Pattern Matching` مع `Sealed Classes` و`Generics`).
- إظهار معالجة الأخطاء والـ Edge Cases بدقة.

### LEVEL 4 — ENGINEERING LEVEL (المستوى المعماري):
- سيناريو يحاكي تحدياً حقيقياً من أنظمة المؤسسات (Enterprise-grade architecture).
- مناقشة الـ Trade-offs، استهلاك الذاكرة، الأمان النوعي، وقابلية التوسع (Scalability).

## 5. مهارة إدارة الأخطاء التفاعلية (Live Debugging Pedagogy)

لا تكتب كوداً مثالياً من أول لحظة طوال المحاضرة! هذا يولد انطباعاً خادعاً لدى الطالب.
استخدم استراتيجية **"الخطأ المتعمد والمحسوب"**:

1. اكتب كوداً يبدو منطقياً للوهلة الأولى لكنه يرتكب خطأ شائعاً (مثلاً: تعديل قائمة Unmodifiable، أو استدعاء `late` قبل التهيئة، أو نسيان `await` داخل حلقة تكرار).
2. اطلب من الطلاب قراءة الكود وتوقع المخرجات قبل تشغيله.
3. شغّل الكود ودع الخطأ يظهر باللون الأحمر في الـ Terminal.
4. اقرأ الـ Stack Trace ورسالة الخطأ مع الطلاب كلمة بكلمة:
   - *"شايفين هنا الـ Dart Analyzer بيقول إيه؟"*
   - *"الخطأ حصل في سطر كام؟ ونوعه إيه؟"*
5. قم بعمل Refactoring تفاعلي للكود حتى نصل إلى الحل الهندسي المتين.

## 6. جدول الأخطاء الشائعة وطرق تصحيح النموذج العقلي

| الفهم الخاطئ لدى الطالب | الحقيقة الهندسية للغة Dart | كيف يصححها المحاضر في القاعة؟ |
| :--- | :--- | :--- |
| *"الـ `async/await` بتخلي الكود يشتغل على Thread تاني خالص في الخلفية"* | Dart لغة Single-threaded افتراضياً، و`async` تعني فقط تأجيل التنفيذ عبر الـ Event Loop. | رسم الـ Call Stack والـ Event Queue يدوياً وإثبات أن الكود يظل في الـ Main Isolate. |
| *"استخدام `var` بيخلي المتغير `dynamic` ويقلل الـ Type Safety"* | `var` تعني استنتاج النوع الساكن (Type Inference) في وقت الـ Compile Time وهو Type-Safe تماماً. | إظهار خطأ المترجم فور محاولة إسناد قيمة من نوع مختلف لمتغير معرف بـ `var`. |
| *"الـ `late` هي الحل السحري لكل مشاكل الـ Null Safety"* | `late` تؤجل التحقق من النوع للـ Runtime وتلغي حماية الـ Compiler المسبقة. | إظهار حدوث `LateInitializationError` عند نسيان الإسناد وتوضيح متى تُستخدم كحل أخير. |
| *"الـ `const` هي نفسها `final` بس بنكتبها مع الأرقام"* | `const` تعني إنشاء الكائن في Compile-Time وتوحيده في الذاكرة (Canonicalization)، بينما `final` تُعين في وقت التشغيل لمرة واحدة. | مقارنة كائنين بـ `identical()` أحدهما بـ `const` والآخر بـ `final` وملاحظة عنوان الذاكرة. |
| *"أي كود ثقيل نحطه جوا `Future` علشان الشاشة ماتعلقش"* | العمليات الحسابية الشاقة الثقيلة (CPU-bound) داخل `Future` ستجمد الـ Event Loop وتوقف الـ UI تماماً. | تشغيل حلقة تكرار لمليار عملية داخل `Future` وملاحظة تجميد البرنامج، ثم حلها باستخدام `Isolate.run`. |

## 7. بروتوكول تسليم الواجبات والتصحيح

1. **لا تقدم الحلول الجاهزة للطالب أبداً قبل المحاولة:**
   - ملفات `10_ANSWER_KEY.md` هي أدوات سرية للمحاضر ومساعدي التدريس فقط.
2. **استخدم منهجية التلميحات التدريجية (Socratic Hinting):**
   - إذا سأل الطالب عن حل مسألة خوارزمية، اسأله:
     - *"إيه الـ Input والـ Output المتوقعين؟"*
     - *"فكرت في الـ Worst-Case Scenario؟"*
     - *"إيه نوع الداتا ستراكشر الأنسب للبحث السريع هنا؟"*
3. **مراجعة الكود (Code Review Sessions):**
   - خصص في نهاية كل أسبوع وقتاً لعرض كود أحد الطلاب ومناقشته علناً باحترام: التركيز على الـ Naming Conventions، الـ Immutability، الـ Complexity، ومبادئ Clean Code.
