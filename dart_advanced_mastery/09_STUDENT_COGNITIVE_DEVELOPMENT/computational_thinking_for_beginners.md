# Computational Thinking & Problem Decomposition for Absolute Beginners
## التفكير الحاسوبي وتفكيك المشكلات: الدليل التأسيسي من الصفر المطلق

> **الافتراض المسبق:**  
> أنت لم تكتب سطراً برمجياً واحداً من قبل، وتظن أن البرمجة تتطلب عبقرية في الرياضيات! الحقيقة المريحة هي: **البرمجة هي مجرد تنظيم للتفكير البشري المنطقي اليومي** بلغة يفهمها الكمبيوتر. الكمبيوتر في الحقيقة جهاز غبي جداً، ولكنه سريع جداً ومطيع جداً؛ ينفذ بحرفية عمياء كل ما تأمره به خطوة بخطوة.

---

## 1. أركان التفكير الحاسوبي الأربعة (The 4 Pillars of Computational Thinking)

كل برنامج عظيم في العالم — من آلة حاسبة بسيطة حتى خوارزميات جوجل — مبني على 4 مهارات عقلية أساسية:

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. التفكيك (Decomposition): تكسير المشكلة الكبيرة لمهام تافهة وصغيرة    │
├────────────────────────────────────────────────────────────────────────┤
│ 2. التعرف على الأنماط (Pattern Recognition): ملاحظة التكرار والتشابه    │
├────────────────────────────────────────────────────────────────────────┤
│ 3. التجريد (Abstraction): إهمال التفاصيل الزائدة والتركيز على المهم     │
├────────────────────────────────────────────────────────────────────────┤
│ 4. تصميم الخوارزمية (Algorithm Design): كتابة وصفة عمل خطوة بخطوة       │
└────────────────────────────────────────────────────────────────────────┘
```

---

### الركن 1: التفكيك (Decomposition)
- **المثال الحياتي:** لو طلبت منك: *"اصنع سيارة"*. ستصاب بالشلل الذهني لأن المهمة ضخمة جداً! لكن لو فككناها:
  1. اصنع هيكلاً معدنياً.
  2. ركب 4 عجلات دائرية.
  3. ضع محركاً في المقدمة.
  4. ركب عجلة قيادة متصلة بالعجلات.
  5. ركب مقاعد ومكابح.
- **في البرمجة:** لو طلب منك برنامج *"إدارة متجر إلكتروني"*:
  - خطوة 1: عرض قائمة المنتجات وأسعارها.
  - خطوة 2: السماح للمستخدم باختيار منتج.
  - خطوة 3: حساب السعر الإجمالي مع الضريبة.
  - خطوة 4: طباعة الفاتورة.
- **القاعدة الذهبية:** *إذا كانت المسألة تبدو صعبة، فأنت لم تفككها لخطوات صغيرة كافية بعد!*

---

### الركن 2: التعرف على الأنماط (Pattern Recognition)
- **المثال الحياتي:** إذا كنت تغسل 20 طبقاً، فأنت لا تخترع طريقة جديدة لكل طبق! أنت تفعل نفس النمط 20 مرة: (ضع صابوناً $\rightarrow$ افرك بالماء $\rightarrow$ جفف $\rightarrow$ ضعه على الرف).
- **في البرمجة:** عندما تجد نفسك تكتب نفس الكود مرتين أو ثلاثة، فهناك "نمط" مكرر يصرخ فيك: *"استخدم حلقة تكرار (Loop) أو ضع هذا النمط داخل دالة (Function)!"*.

---

### الركن 3: التجريد (Abstraction)
- **المثال الحياتي:** خريطة مترو الأنفاق في القاهرة لا ترسم لك كل شارع وعمارة وشجرة في المدينة! هي فقط ترسم خطوطاً مستقيمة ومحطات؛ لأن كل ما يهمك كراكب هو: أين أركب؟ وأين أنزل؟
- **في البرمجة:** عندما ننشئ كائناً يمثل "طالباً في المدرسة"، نحن نهتم بـ: (اسمه، صفه الدراسي، درجاته). لا نهتم بلون حذائه أو طعامه المفضل؛ لأنها تفاصيل زائدة لا تخدم هدف البرنامج.

---

### الركن 4: تصميم الخوارزمية (Algorithm Design)
- **المعنى:** "الخوارزمية" كلمة تبدو مرعبة، لكنها في الحقيقة مجرد: **وصفة طهي (Recipe)** دقيقة ومرتبة خطوة بخطوة.
- **مثال خوارزمية سحب نقود من الصراف الآلي (ATM):**
  1. انتظر إدخال البطاقة.
  2. اطلب الرقم السري (PIN).
  3. **قرار (Condition):** هل الرقم السري صحيح؟
     - إذا نعم: اعرض قائمة الخيارات.
     - إذا لا: اطلب إعادة المحاولة (بحد أقصى 3 مرات).
  4. استقبل المبلغ المطلوب سحبه.
  5. **قرار (Condition):** هل رصيد الحساب يغطي المبلغ؟
     - إذا نعم: أخرج النقود واخصم من الرصيد.
     - إذا لا: اعرض رسالة "الرصيد لا يكفي".
  6. أرجع البطاقة للمستخدم واطبع الإيصال.

## 2. اللبنات الأساسية لأي لغة برمجة في العالم

كل لغات البرمجة (من Dart إلى C++ إلى Python) تتكون من 5 لبنات أساسية فقط:

```
1. الصناديق (Variables & Data Types): تخزين الأرقام والنصوص في الذاكرة.
2. اتخاذ القرار (Conditions): إذا تحقق شرط كذا.. افعل كذا.. وإلا افعل شيئاً آخر.
3. التكرار (Loops): كرر هذه الأوامر 100 مرة أو طالما أن الشرط صحيح.
4. الوصفات القابلة للاستخدام (Functions): تجميع عدة خطوات في اسم واحد واستدعاؤها عند الحاجة.
5. تنظيم البيانات (Collections): ترتيب عدة عناصر في قائمة واحدة (List) أو قاموس (Map).
```

---

## 3. الصناديق والذاكرة: كيف نخزن البيانات؟ (Variables as Labeled Boxes)

تخيل الذاكرة (RAM) في الكمبيوتر كـ مخزن عملاق مليء بمليارات الأدراج أو الصناديق الكرتونية:

```text
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│   الصندوق: age    │      │   الصندوق: name   │      │ الصندوق: isOpen  │
│   النوع: int     │      │   النوع: String  │      │  النوع: bool     │
│   ────────────   │      │   ────────────   │      │  ────────────    │
│   القيمة: 25     │      │   القيمة: "أحمد"  │      │  القيمة: true    │
└──────────────────┘      └──────────────────┘      └──────────────────┘
```

- **قاعدة الأمان:** في Dart، لكل صندوق "نوع محدد" مكتوب عليه:
  - صندوق `int`: مخصص للأعداد الصحيحة فقط (أعمار، عدد طلاب، تكرارات: `25`, `-5`, `0`).
  - صندوق `double`: مخصص للأرقام ذات الفواصل العشرية (أسعار، حرارة، أوزان: `19.99`, `36.6`).
  - صندوق `String`: مخصص للنصوص والكلمات، ونميزه دائماً بعلامات التنصيص: `"عمر"`, `"Cairo"`.
  - صندوق `bool`: مفتاح كهربائي له حالتان فقط: `true` (مضاء/صح) أو `false` (مغلق/خطأ).

## 4. كيف نقرأ كود Dart ونتتبعه بالعين؟ (Visual Code Tracing)

انظر إلى هذا البرنامج البسيط:
```dart
void main() {
  int price = 100;
  int discount = 20;
  int finalPrice = price - discount;
  
  if (finalPrice > 50) {
    print('سعر الصفقة: $finalPrice جنيه');
  } else {
    print('السعر رخيص جداً!');
  }
}
```

### جدول تتبع الذاكرة باليد (Memory Tracing Table):

| السطر | الصندوق (Variable) | نوعه (Type) | القيمة الحالية (Value) | ماذا يفعل الكمبيوتر في هذه اللحظة؟ |
| :---: | :--- | :--- | :--- | :--- |
| **2** | `price` | `int` | `100` | تم حجز صندوق اسمه price ووضع الرقم 100 بداخله. |
| **3** | `discount` | `int` | `20` | تم حجز صندوق اسمه discount ووضع الرقم 20 بداخله. |
| **4** | `finalPrice` | `int` | `80` (100 - 20) | قام المعالج بحساب `100 - 20` وحفظ الناتج في صندوق جديد. |
| **6** | — | — | الشرط: `80 > 50` $\rightarrow$ `true` | فحص الشرط: هل 80 أكبر من 50؟ نعم (صواب)! إذن ندخل فرع الـ if. |
| **7** | شاشة العرض (Console) | — | `"سعر الصفقة: 80 جنيه"` | طبع النص على الشاشة مع استبدال `$finalPrice` بقيمتها. |
| **8** | — | — | — | تجاهل فرع `else` بالكامل لأن الشرط تحقق. |

## 5. عقلية المبتدئ الشجاع عند ظهور الأخطاء (Error Mindset)

- **الحقيقة التي لا يخبرك بها أحد:** كبار المهندسين في جوجل يظهر لهم أخطاء حمراء في الـ Terminal عشرات المرات كل يوم!
- **الخطأ ليس إهانة لذكائك:** رسالة الخطأ هي **رسالة مساعدة وصديق مخلص** من المترجم يخبرك بالضبط:
  - أين المشكلة؟ (رقم السطر ورقم العمود).
  - ما نوع المشكلة؟ (مثلاً: أنت نسيت فاصلة منقوطة `;`، أو وضعت كلمة مكان رقم).
- **قاعدة الـ 3 خطوات عند ظهور الخطأ:**
  1. خذ نفساً عميقاً ولا ترتبك.
  2. اقرأ السطر الأخير في رسالة الخطأ ببطء.
  3. اذهب للسطر المذكور في الكود وافحصه بهدوء.
